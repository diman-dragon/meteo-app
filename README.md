# Meteo — прогноз погоды (Capacitor 8, Android)

Данные: [Open-Meteo](https://open-meteo.com/) — прогноз (current / hourly / daily, все поддерживаемые параметры, 16 дней), качество воздуха и пыльца, геокодирование.

## Что умеет
- Обновление **только по нажатию** «Обновить». Автозапросов нет (проверяется скриптом). В мобильной сети — подтверждение при каждом обновлении.
- Место вручную: поиск города или координаты. Разрешения на геолокацию нет.
- Настройки открываются шестерёнкой: версия приложения, тема (тёмная / светлая), язык (авто / русский / English), место и **единицы измерения**.
- **Единицы:** готовые стандарты (Метрический, Россия, США, Великобритания) и ручной выбор: температура °C/°F, ветер км/ч · м/с · миль/ч · уз, осадки мм/дюймы, давление гПа · мм рт. ст. · inHg · кПа, расстояния (видимость, высота, снег) метрические/имперские. Данные всегда запрашиваются в метрике, а пересчитываются на экране — поэтому смена единиц мгновенная, без нового запроса, и кэш не портится.
- Страницы листаются свайпом (или вкладками сверху): Сводка · Температура · Осадки · Ветер · Воздух · Атмосфера · Солнце · Дни · История. Системная «назад»: из настроек — на предыдущий экран, со страницы — на «Сводку»; на «Сводке» остаётся (приложение не закрывается).
- «Сводка» — хаб: погода сейчас, лента на 12 часов и плитки Температура / Осадки / Ветер / Воздух / Атмосфера / Солнце. Нажатие на плитку открывает подробную страницу темы.
- Графики (чистый SVG, без библиотек) на каждой странице темы: 48 часов и 16 дней; касание графика показывает значение. Все параметры Open-Meteo выведены списками «Сейчас» и «Сегодня»; нажатие на час или день — полный набор параметров.
- **История:** выберите дату (с 01.01.1940 по вчера) или быстрые кнопки «Вчера / 7 дней назад / Год назад» — получите такую же сводку, графики и все дневные параметры за этот день. Последние 90 дней берутся из forecast API (там же есть качество воздуха), более ранние — из archive API (ERA5). Запрос только по нажатию «Показать».
- Иконки погоды нарисованы в SVG; «небо» в верхней карточке меняется от погоды и времени суток.
- Офлайн: последний прогноз хранится на устройстве.
- Нажатие на час или день — все параметры Open-Meteo; в дне — ещё и все 24 часа.

## Строгая атомарность (одна ответственность — один файл)
`npm run check` (и CI) падает, если:
- в файле больше одного `export` или функции; имя файла ≠ имени экспорта; файл длиннее 40 строк (данные в `config/` и `i18n/` — до 120);
- есть мёртвый файл, `localStorage`, `innerHTML`, `eval`, `fetch` вне `api/fetchJson.js`;
- `refreshWeather` импортирует кто-то кроме `refreshButton`, запросы погоды вызываются не из `refreshWeather`, есть `setInterval`/авто-триггеры;
- в `ru`/`en`/`*Vars`/`*Wmo` разные ключи, использован `t('…')` без перевода, у переменной Open-Meteo нет подписи.

## Структура `src/`
| Папка | Ответственность |
|---|---|
| `config/` | константы и списки переменных Open-Meteo |
| `api/` | URL-билдеры и сетевые функции |
| `storage/` | чтение/запись Preferences |
| `state/` | единый объект состояния |
| `network/` | тип подключения |
| `i18n/` | словари и переводчики |
| `domain/` | чистые функции форматирования |
| `flows/` | сценарии (обновить, выбрать место, тема, язык, старт) |
| `navigation/` | экраны и кнопка «назад» |
| `theme/` | тема и системные панели |
| `ui/` | компоненты, графики (`charts/`), иконки (`icons/`), страницы (`pages/`), свайп (`pager/`), экраны (`el.js` — безопасное создание DOM) |
| `styles/` | один CSS-файл на ответственность; темы в `themes/` |

## Запуск
```bash
nvm use            # Node 22
npm ci
npm run check      # атомарность
npm run dev        # браузер
npm run android:debug   # нужен Android SDK + JDK 21
```
Открыть в Android Studio: `npx cap open android`.

## GitHub и подписи
- `ci.yml` — на push/PR: check → build → **debug APK** (артефакт `meteo-debug-apk`).
- `release.yml` — на тег `vX.Y.Z`: **APK + AAB** (артефакт `meteo-release`).

### Одна несекретная подпись (разработка)
Все сборки — и debug, и release, и локальные, и из Actions — подписываются **одним и тем же ключом** `android/keystore/dev.keystore`.
Он лежит в репозитории (пароль `android`, алиас `meteodev`) и **не секретный**. Поэтому новая сборка ставится **поверх** старой как обновление, данные приложения сохраняются.

Чтобы обновление сработало, нужны три вещи (все уже настроены):
1. тот же `applicationId` (`dev.meteo.weather`) — не менять;
2. та же подпись — dev-ключ;
3. `versionCode` больше установленного: он считается автоматически как «минуты с 01.01.2026 UTC», растёт с каждой сборкой, откуда бы она ни была.

Отпечаток для сверки: `keytool -list -v -keystore android/keystore/dev.keystore -storepass android` (SHA-256 `6A:F9:B4:07:…:50:B8:DA`). В логе каждого CI-запуска печатается сертификат собранного APK — он должен совпадать.

Если на телефоне стоит сборка со **старой** (случайной debug) подписью, один раз удалите её — дальше обновления пойдут без переустановки.

### Когда дойдёте до Google Play
Публичный ключ нельзя использовать как ключ загрузки. Создайте настоящий и добавьте секреты репозитория `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`; `release.yml` сам переключится на него:
```bash
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 upload.jks     # → KEYSTORE_BASE64
```
Учтите: приложение из Play подписывается ключом Play App Signing, поэтому сборку с dev-ключом придётся один раз удалить перед установкой из Play.

Версия: меняйте только `package.json` (`versionName`). Тег должен совпадать: `v1.3.1`.

## Перед публикацией
Смотрите `docs/PLAY_CHECKLIST.md`. Обязательно: сменить `applicationId`, URL политики конфиденциальности (`src/config/privacyPolicyUrl.js`), e-mail в `docs/privacy-policy.md`.
